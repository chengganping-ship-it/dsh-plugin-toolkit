# Recovery Agent · 客户试点SOP

> 目标：14天内找到3个真实客户，验证付费意愿

---

## 第1-2天：锁定垂直行业

**不要凭感觉选。优先选择你能接触到客户的行业。**

决策矩阵：

| 行业 | 客户可达性 | 数据可获取性 | 异常频率 | 付费意愿 | 推荐 |
|------|-----------|-------------|---------|---------|------|
| 跨境电商 | 高（微信群/知乎/即刻） | 高（卖家都Excel对账） | 极高 | 高 | ⭐⭐⭐⭐⭐ |
| 物流专线 | 低（需 BD） | 中 | 高 | 中 | ⭐⭐⭐ |
| SaaS | 中 | 高 | 中 | 高 | ⭐⭐⭐⭐ |
| 外贸工厂 | 低 | 低 | 中 | 中 | ⭐⭐ |

**推荐首选：跨境电商**

理由：
- 物流费用占比高（10-30%销售额）
- 丢件/延误/扣费是常态
- 卖家微信群活跃，容易触达
- 数据简单（都是Excel）
- 痛点明确（"钱被平台和物流扣了不知道"）

## 第3-5天：准备交付材料

### 必须准备
1. **演示报告**（已有：用demo数据生成）
2. **简单合同/协议**（约定服务费、数据保密）
3. **数据接收说明**（告诉客户怎么给你数据）

### 话术：第一次联系

如果是微信/邮件触达：

```
你好，我叫[名字]，做一个帮助跨境电商卖家"找回被平台和物流多扣的钱"的服务。

做法：你把最近1-3个月的订单表、结算单、物流账单发给我（脱敏即可），我用系统自动分析：
1. 哪些丢件没申请赔偿
2. 哪些延误没申请索赔  
3. 哪些退款没有回到账上
4. 平台是否重复扣费
5. 订单金额和结算是否一致

免费审计。找到可追回的钱后，我们再谈合作。追回才收费，收15-25%。

最近一个案例：一个卖家100笔订单，发现¥5,300可追回的异常。

你方便看一份演示报告吗？
```

## 第6-10天：试点交付

### Step 1: 数据接收

发送数据接收说明：

```
请准备以下数据（可以脱敏去掉买家姓名）：
□ 订单表：订单号、金额、产品、日期、平台
□ 结算表：结算ID、订单号、结算金额、费用、日期
□ 物流表：运单号、订单号、状态、运费、重量、日期
□ 退款表（如有）：退款ID、订单号、退款金额、日期

格式要求：Excel(.xlsx)或CSV，文件名英文
数据时间范围：最近1-3个月

请发送到 [邮箱/微信]
```

### Step 2: 数据清洗

客户数据往往不规范，常见问题：
- 列名中英文混用
- 日期格式不统一
- 金额带货币符号
- 运单号在订单表/物流表列名不同

**处理方式**：用AI快速映射字段

```python
# 把客户的列名告诉我，我帮你生成映射
客户列名: "单号,金额,时间,运单编号,物流状态"
我的字段: order_id, amount, date, tracking_no, status

映射：单号→order_id, 金额→amount, ...
```

### Step 3: 运行审计

```bash
python main.py --customer [客户ID] --dir data/[客户ID] --output data/output/[客户ID]
```

### Step 4: 生成报告

生成客户版报告（隐藏技术细节，突出"你的钱去哪了"）：

```
[C客户名称] 资金回流审计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📊 审计范围
  订单：X笔 | 结算：Y笔 | 运单：Z笔
  时间：2026年X月 — 2026年X月

💰 发现的异常

1. 物流丢件未索赔（2单）
   → 可追回约 ¥XXX
   运单1：SF123456，2026-XX-XX丢件，货物价值¥XXX
   运单2：YT789012，2026-XX-XX丢件，货物价值¥XXX

2. 平台重复扣费（3笔）
   → 可追回约 ¥XXX
   订单A：2026-XX-XX，¥XXX被收取二次
   ...

📋 总计
  异常数量：X条
  预估可追回：¥X,XXX
  我们服务费（20%）：¥X,XXX
  
🔧 下一步
  如确认无误，我们协助生成索赔材料并追踪。
  追回后收取服务费，收15-25%。
```

### Step 5: 客户确认

发送确认模板：

```
已出报告，预估可追回 ¥X,XXX：

1. 请确认以上异常是否属实
2. 确认后我们生成正式索赔材料
3. 协助你向平台/物流提交
4. 实际到账后才收费

确认后我们开始操作，有问题随时沟通。
```

## 第11-14天：决策点

### 继续的条件（全部满足）
- 至少2/3个试点发现真实可处理的异常
- 至少1个客户愿意付费
- 预估追回金额明显高于成本
- 客户能提供持续数据

### 不继续的信号
- 客户数据太乱，无法结构化
- 异常金额太小（< ¥500）
- 客户只想免费要报告，不想付费追回
- 行业本身物流/结算异常率极低

---

## 价格策略

### 小额订单（追回<¥5,000）
```
一次性收费：¥500-1,000（不收成功费）
原因：金额小，索赔成本高，线性定价更合适
```

### 中额订单（追回¥5,000-50,000）
```
纯成功费：到账金额 × 20%
原因：客户零风险，你有足够利润空间
```

### 高频大客户（每月持续）
```
月费：¥2,000-5,000
+ 追回金额 × 10-15%
原因：月费覆盖基础成本，成功费保持激励
```

## 关键成功指标（KPI）

| 指标 | 目标 | 描述 |
|------|------|------|
| 数据接收成功率 | > 80% | 发给说明后，客户真的发数据 |
| 异常发现率 | > 60% | 数据中发现异常的客户比例 |
| 首次审计时效 | < 4小时 | 从收到数据到出报告 |

| 索赔提交成功率 | > 70% | 提交后未被直接拒绝 |
| 30天追回率 | > 30% | 提交后30天内实际到账 |

## 风险与应对

### 风险1：客户数据包含敏感信息
**应对**：明确说明只需脱敏数据（去掉买家/卖家姓名、地址），保留订单号和金额即可。签数据保密协议。

### 风险2：异常误报
**应对**：系统标注"置信度"，低置信度异常不纳入报告。人工复核后再发给客户。

### 风险3：客户私下索赔后不付服务费
**应对**：
- 证据包中嵌入你的联系信息（索赔时卖家需要提供支持证明）
- 合同约定"自审计日起12个月内，如发生基于本报告异常性质的追回，服务费仍应支付"
- 先发小额（¥500），建立信任后再做大额

### 风险4：平台政策变化导致索赔困难
**应对**：多元化异常类型，不只依赖单一平台规则。物流丢件/延误是普适性事件。
