## 一、开工闸门 (必须全部勾选 = GO)

### 客户入口

- [ ] 已与首客户签订服务合同, 包含数据处理条款
- [ ] 客户明确授权"使用 AI 处理其提供的询盘数据"(邮件 or 合同)
- [ ] 客户知晓"哪些环节是人工审批, 哪些是自动化"
- [ ] 客户已同意"数据脱敏处理方式"

### 数据分类

- [ ] 接触到的数据已按 L0-L3 分级 (见 § 二)
- [ ] 核心图纸 (L3): 先用 PaddleOCR 本地 OCR, 不传到任何外部 API
- [ ] 客户联系信息 (LII): 抽取时自动脱敏 (公司名 → "某 Sample", 邮箱 → "已脱敏")
- [ ] 已签订《数据处理协议》(DPA) 或 DPA 条款写入主合同

### 模型选型

- [ ] P1 默认使用 **本地部署模型** (Ollama + Qwen3-72B 或客户同等级)
- [ ] 若使用国内 API (智谱/MiniMax), 已与供应商签订 DPA
- [ ] 境外 API (OpenAI 等) 仅在客户书面单独授权时使用 (P1 建议不用)

### 基础设施

- [ ] 服务器位于中国内地 (不含港澳台)
- [ ] 磁盘加密已启用 (LUKS / BitLocker)
- [ ] API Key / 密码在 .env 文件, 不在代码或 git 仓库
- [ ] 飞书 API Scope 为最小权限

### 自动化红线

- [ ] 自动发送 SMTP 在 P1 阶段 **硬编码禁用**
- [ ] 删除操作仅在飞书人工标记 "customer_deletion_request" 后执行
- [ ] 所有外部消息发送必须有人工点击 "批准"
- [ ] AI 输出中, "价格/交期/认证/合同"字段为 null, 系统不输出文本

## 二、数据分级 (L0-L3)

| 等级 | 内容 | 示例 | 处理要求 |
|------|------|------|---------|
| L3-高 | 核心图纸、大客户合同、核心配方 | 客户 STEP 文件 | 本地 OCR 后立即删除源, 只用元数据 |
| L2-中 | 产品图、报价、客户名单、客户询盘 | 供应商 Excel | 加密 + 7 天后 LLM 缓存清除 |
| L1-低 | 行业公开资料、已成交历史询盘 | 官网信息 | 标准保护 |
| L0-无 | 系统元数据 | 处理时间、错误码 | 无要求 |

**RFQ 项目最常接触**: L2 (附件 + 正文) 和 L1 (询盘内容)
**严格禁止接触**: L3 (除非客户已授权 + 书面同意处理方式)

## 三、保留与删除

| 数据类型 | 保留期 | 删除方式 |
|----------|--------|---------|
| 原始附件 (脱敏后) | 合同结束 + 30 天 | 软删除 → 30 天后硬删 |
| LLM 中间结果 | 调用后 72 小时 | 定时脚本清理 |
| 结构化 RFQ 表 | 合同结束 + 保留 | 飞书多维表格长期保留 |
| 审计日志 | 1 年 | 轮转删除 |
| 客户标记删除的数据 | 收到请求 15 天内 | 全部系统硬删 + 客户确认 |

## 四、硬编码不得违反的红线

| 红线 | 实现方式 |
|------|---------|
| 不得主动 SMTP 发信 | n8n Workflow 中不含 SMTP 节点 |
| 不得伪装员工与客户谈判 | 回复草稿顶部固定"Not sent by real person" |
| 不得抓取客户历史邮箱全量 | 只用客户专门转发的邮件 |
| 不得把数据用于训练 | 模型 API 设置 "不训练" + 本地优先 |
| 不得跨境传输 | 模型选本地或国内 DPA 供应商 |
